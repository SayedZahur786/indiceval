INDICEVAL / RESEARCH PREVIEW

Methodology & limitations

IndicEval v0.1 is a research preview for single-turn coding and reasoning capabilities. It evaluates outputs from agent backends; it does not measure autonomous planning, tool use, or repository-level engineering.

The first 50 source records are used for code, math and causal reasoning. Reading uses the first 50 records whose accepted answers all occur verbatim in the supplied context. Excluded source IDs are recorded in the exclusion ledger. This is a convenience sample, not a random or representative sample.

Review status is explicit

150 tasks retain the original source's documented human translation/review evidence. We verify reference execution, arithmetic annotations, source-label fidelity and answer spans. These checks are not an independent human adjudication of every answer.

The 50 Hinglish coding prompts are new adaptations of human-written English problems. Their reference solutions pass the original tests, but the Hinglish language adaptations require independent review. This is not a fully hand-checked 200-task release. Review evidence is visible in each task.

Scoring contracts

  • Code: complete Python code, optionally inside one Python code fence, passes the upstream tests in an unprivileged Docker container. Network disabled, no host mounts, read-only root, bounded CPU, memory, process count, output and execution time.
  • Math: a single finite number, compared using decimal arithmetic. Unicode digits and whitespace are normalized. Explanations and units fail the specified format.
  • Causal: exactly 1 or 2 after whitespace and Unicode normalization, matched to the source label.
  • Reading: normalized exact match to any accepted reference. Case and punctuation are preserved. Semantically valid paraphrases can be marked wrong.

Metrics and repetitions

Accuracy is the fraction of tasks passed by the first sample, averaged across repetitions. pass@k uses 1 − C(n−c,k) / C(n,k), averaged over task/repetition groups, where n is samples and c is passing samples. k must not exceed n. See the HumanEval estimator.

At least two repetitions are required for submissions. Seeds vary by repeat and sample; a provider may ignore seed requests. We report each repetition's accuracy, sample variance (denominator R−1), and range. Variance is in squared proportion units. Two repeats are not a confidence interval and cannot establish ranking significance.

Latency measures each API request's wall time, including HTTP overhead, excluding local grading. p95 uses nearest-rank selection. Cost is an estimate from provider-reported prompt/completion tokens and user-declared prices per million tokens. Cost per task includes all n samples and is averaged over task/repetition groups. Missing token usage or pricing produces unknown total cost. Cached-token pricing, tool fees and local hardware cost are not estimated.

HTTP failures, malformed outputs, timeouts and wrong answers remain in the denominator. Requests are not automatically retried. An unavailable code sandbox aborts the run rather than creating a misleading score. Partial artifacts cannot pass submission validation.

Contamination and comparison limits

These are public benchmark derivatives. They may be in model training data, and the original HumanEval tests are widely exposed. We cannot certify contamination-free evaluation. Submitters must disclose known training exposure, retrieval, tools, prompt changes and model versions. Keep benchmark tasks out of training when reporting evaluation scores; licences may legally permit uses beyond this research recommendation.

Task type and language are completely coupled in this preview. A difference between Hindi and Tamil strata could be caused by task type, not language. Do not interpret the breakdowns as a controlled comparison of languages. English controls exist for the code stratum only and are not a second counted dataset.

Public tests do not establish exhaustive correctness or protect against deliberate test exploitation. Containers reduce execution risk but are not a hardened public multi-tenant service. Review untrusted submissions in a disposable environment. The static site never executes submitted code.

Evidence and versioning

Task hashes, dataset SHA-256, source revision IDs, raw samples and run settings are preserved. Download the manifest and inspect verification evidence. A reference-answer fixture validates plumbing, not model capability, and is excluded from rankings.

Research context

IndicEval builds on HumanEval, GSM8K-Hi, XCOPA and IndicGenBench. This independent project is not affiliated with IndicEval-XL, HinglishEval, or other projects called IndicEval. No claim of scientific novelty or superior model performance is made.
